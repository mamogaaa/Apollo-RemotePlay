# Remote Play host: исследовательский прототип

Цель: ПК с Apollo обслуживает неизменённые штатные клиенты PS5 (профиль
сервера PS4) и PS4 (профиль сервера PS5). По приоритету пользователя сначала
получаем работающий стрим в Chiaki-ng, затем проверяем настоящие консоли.

## Подтверждено сейчас

- LAN discovery PS4/PS5: UDP 987 / 9302.
- Поиск сервера регистрации SRC2/RES2 и SRC3/RES3: UDP 9295.
- Регистрация по PIN обоих профилей: TCP 9295, зашифрованные запрос/ответ.
- Интеграционный тест вызывает **неизменённые функции регистрации Chiaki-ng**:
  настоящий UDP/TCP обмен, правильный PIN принят, неправильный отклонён,
  ответ разобран клиентом, ключи сохранены сервером.
- Шесть автоматических тестов discovery, хранения состояния, разбора запросов,
  истечения окна привязки и явно неподдерживаемого старта сессии.

Это ещё НЕ игровой сервер. Запуск сессии возвращает 501, видео/звук/ввод
не реализованы. GUI Chiaki и физические консоли пока не проверены.
Профили используются одновременно на одном адресе; поведение штатного
клиента при таком объявлении ещё требует проверки.

## Воспроизведение (Linux, Python >= 3.11, C compiler, OpenSSL development files)

Из корня этого репозитория, исходники Chiaki расположены рядом:

```sh
git clone https://github.com/chiaki-ng/chiaki-ng.git ../chiaki-ng
git -C ../chiaki-ng checkout 43728af2e639fecb8a7af1cd68c29820a40de973
git -C ../chiaki-ng submodule update --init third-party/jerasure third-party/gf-complete
python tools/remoteplay/build.py ../chiaki-ng
python -m unittest discover -s tools/remoteplay/tests -v
python tools/remoteplay/tests/integration.py
python tools/remoteplay/host.py --bind 127.0.0.1
```

Интеграционный тест занимает UDP/TCP 9295 на loopback. Остановить другой
прототип перед его запуском. Тест не меняет настоящее сохранённое состояние.
Полная GUI-сборка Chiaki не нужна: linker удаляет неиспользуемые функции
из исходников. Клиентские исходники не патчатся.

Для внешнего Chiaki запустить host с `--bind <LAN-IP-ПК>` и разрешить входящие
UDP 987, 9302, 9295 и TCP 9295 в локальном firewall. Доступность UDP 987
зависит от прав ОС на порты ниже 1024. Использовать выведенный восьмизначный
PIN и свой Account ID в клиенте. Облачный экземпляр не находится автоматически
в домашней LAN пользователя.

PIN генерируется при запуске и действует 300 секунд; после пяти неуспешных
проверок с одного IP регистрация с него блокируется до перезапуска. Файл
state.json содержит секреты, создаётся с правами 0600 и исключён из Git.
Секреты не выводятся в диагностические логи. Это лабораторный сервер IPv4,
не предназначенный для публикации в интернете. Идентичности профилей
генерируются один раз и сохраняются; это не реальные идентичности Sony/PSN.

## Следующие этапы и критерии

1. **Сессия:** загрузить сохранённый RegistKey/RP-Key, реализовать init,
   RP-Nonce и control-канал. Проверять валидные и невалидные ключи, повторный
   вход после перезапуска, таймауты и закрытие соединений.
2. **Тестовый стрим:** Senkusha/MTU, Takion INIT/COOKIE, BIG/BANG, ECDH,
   STREAMINFO, H.264 720p60 SDR, стерео Opus, packetization/FEC и ввод.
   Приёмка: неизменённый Chiaki показывает движущийся счётчик кадров,
   воспроизводит звук, отправляет кнопки; проверить оба профиля.
3. **Apollo:** общий интерфейс закодированных кадров/аудио/ввода,
   отдельный Remote Play transport, запуск игры, освобождение ресурсов.
   Не переводить видео через дополнительное декодирование/кодирование.
4. **Обычные консоли:** PS5→профиль PS4 и PS4→профиль PS5. Настоящая PS4
   у пользователя есть, аппаратные проверки отложены по его указанию.
   Результат Chiaki не заменяет эту приёмку.
5. **Качество:** 1080p60 при поддержке профиля, час игры по Ethernet,
   серия reconnect, измерения latency/frame pacing/AV sync и потерь.

## Основания и ограничения

Исследован Apollo adc5c5a0bd80831ce495434bb16aee2cd4175fb8 и Chiaki-ng
43728af2e639fecb8a7af1cd68c29820a40de973.

- Chiaki lib/src/discovery.c и lib/include/chiaki/discovery.h: discovery.
- lib/src/regist.c: запрос/ответ регистрации, пути, payload и UDP search.
- lib/src/rpcrypt.c: LAN aeropause = (ambassador XOR table) + offset + i.
  Функция ambassador_from_aeropause обращает PSN-вариант, поэтому LAN inverse
  реализован отдельно, с таблицей, получаемой через публичную aeropause().
- lib/src/session.c, ctrl.c, streamconnection.c, takion.c: следующие этапы.
- Apollo src/video.h, audio.h, input.cpp, stream.cpp: точки будущей интеграции.

RP-KeyType=2 пока экспериментальное значение: принят тестом регистрации,
совместимость последующей сессии и Sony не доказана. Поддерживаются современные
профили PS4 RP 10.0 и PS5 RP 1.0; старые PS4 и PSN holepunch не реализованы.
